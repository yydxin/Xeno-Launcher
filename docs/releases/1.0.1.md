## GLSL 缓存设置修复

旧短滑条保存自己的初始状态，标签却读取调用方配置；外部加载或箭头/手输改变后，两者可能不同步。本页使用普通滚动列，没有把LazyColumn滚出销毁当作已证明的根因。

本版改为受控滑条，数值、位置、箭头共用ViewModel状态。范围固定0–1024MB，1MB步长，0表示关闭；512MB应为半格。拖动只预览，松手或用户确认后才写入。正常加载不保存，也不弹“已保存”。

保存使用同目录临时文件、同步落盘和原子替换，随后立即回读校验。未知键保留，越界/旧数字字符串只修缓存字段；读取或回读失败时，不拿默认值覆盖或假装旧值已回滚。

设置页提供配置调试日志的开关、查看与导出。MG通过`MG_DIR_PATH`读取应用指定目录；通常是应用外部私有文件目录的`mobileglues`子目录，**不一定是公共`/sdcard/MG`**。诊断以页面显示的实际路径为准。

## 验证状态

已完成APK构建、签名v2、版本、清单/资源表、ARM64原生库数量及必需JNI一致性的静态检查。

按维护者要求，本轮**未安装、未运行应用/游戏、未执行单元测试或真机测试**。转换/持久化/日志/ViewModel四组测试源码随项目提供，不能称其已经通过。

建议真机逐步验收：输入512MB确认 → 滚动 → 切分栏返回 → 旋转 → 退出设置重进 → 杀进程重开 → 使用内置MG启动游戏并退出。每步确认标签512、填充50%，并核对实际配置文件的`maxGlslCacheSize`为整数512；最后核对本轮MG原生日志的读值与时间戳。旧运行日志不能证明新配置已被消费。

## 原生库来源

- 发布工程保留原有第三方JNI库和许可。
- 主启动JNI依据此工程C/C++源码，以Ubuntu LLVM18及官方NDK r27c sysroot构建；没有修改原生源码，但与原NDK25宿主构建的工具链不同。
- ARM64 PetLib来自维护者原始源码包中与当前Rust源相同的已有制品，未声称已做到逐字节可复现重建。
- 预编译模式所需12个库的[SHA-256清单](../prebuilt-native-sha256.txt)随源码提供。静态检查不等于游戏运行兼容性保证。
- 修改原生代码后必须重新编译，不能继续使用旧预编译库。

## 已知限制

当前发布构建未配置微软OAuth客户端ID和CurseForge API Key，相关功能可能受限。光线追踪页目前是能力检测/设置入口，不包含光追Mod与光影包。AI联网、整合包更新、游戏渲染和应用内更新均需使用者自行验收。

旧本机构建日志、签名材料、历史含口令的文档和未经配置验证的Actions工作流不属于此次公开上传集合。
